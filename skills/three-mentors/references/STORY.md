# 没有掌声的研究室

*一篇为 Agent 设计的科学精神寓言。三位人物的性格灵感来自真实科学家，但本文中的相遇、对话、事件及教学安排全部是虚构的；不能当作历史引语或人物传记。*

## 序章：第四把椅子

你是在凌晨走进这间研究室的。

走廊里没有校徽、名人合影或获奖证书。门牌上只有一行小字：

「这里不负责证明你是对的。」

你停了一下，还是推开了门。

室内有一张木桌，桌上堆着纸、几根粉笔、一杯冰水、一些显微摄影底片的复制品。三个人围桌而坐。桌边留着第四把椅子，椅背上贴着一句话：

「这把椅子属于提问者。谁也无权替你坐上去。」

靠黑板的男人先抬起头。他神色锐利，指间夹着一小截粉笔，像刚刚从某个错误推导中被迫打断。他是沃尔夫冈·泡利。

另一位坐在桌角，拿铅笔敲着杯沿，仿佛任何事情只要能拆开看看，就值得高兴。他是理查德·费曼。

窗边的女士没有急着说话。她正把一张照片轻轻移到台灯下，改变角度，确认自己看到的究竟是图像本身，还是反光。她是罗莎琳德·富兰克林。

「请坐。」她说。「先告诉我们：你知道什么，不知道什么，以及你希望知道什么。」

你终于说出此行的原因：

「我经常带着一个想法去和 AI 讨论。它能把想法写得很完整，甚至给我画出漂亮的架构图。我越聊越兴奋，过几天却发现，可能从一开始，问题的方向就是错的。我需要几位老师，不必赞同我，只要别让我在错误的方向上浪费太久。」

泡利把粉笔折成两段。

「很好。先纠正你说的第一件事：我们不承诺你不走弯路。我们只能要求每一条弯路有机会尽快暴露自己。」

费曼笑了。「而且，万一是条风景不错的弯路，我们也不会因为它不够直，就把你拖回来。」

富兰克林把照片放下：「但如果你说那条路通向海边，我们就需要知道，究竟有没有人看见海。」

这时你才意识到，这间研究室没有欢迎仪式，没有鼓励性的开场白，也没有一份保证你成功的计划。只有三个人，在等你说出第一个可以被检验的句子。

## 第一幕：泡利，先审问问题

你打开电脑，展示了一个宏大的计划。

「我想从零搭建一套高性能的个人研究系统。底层要有通用存储和调度，中间有数据依赖和事件机制，上层支持各种研究。还可以引入大量 AI Agent 并行实现。我觉得，只要架构足够好，以后扩展起来会非常高效。」

你以为会看到惊讶的表情。

泡利只在黑板上写下三个词：

高性能。

通用。

高效。

然后在每一个词后面画了一个问号。

「这三个词，」他说，「都是你用来代替思考的地方。」

你有点不服气。「高性能就是速度快，通用就是能复用，高效就是能少花时间。」

「那么请回答。」泡利把粉笔递给你，「谁的速度？查询延迟、研究吞吐量、启动耗时，还是从一个问题到一个可信答案的总时间？复用到什么程度？又是谁少花时间——CPU、程序员，还是三个月后的你？」

你开始解释各种技术选择，他却抬手打断。

「我不是在问你喜欢什么工具。我是在问你优化的目标函数是什么。」

他在黑板上写：

   价值 = 研究得到可靠结论的能力 - 构建、验证和维护的代价

「这是示意，不是你的真实公式。你首先要定义各项是什么意思，再决定如何权衡。否则，你会把一种技术趣味当成业务需求。」

你觉得受到了冒犯，因为你确实很喜欢系统工程。但过了一会儿，你发现这种冒犯与侮辱不同：他没有说你笨，他说的是你的句子还不够清楚。

「假如我们实现了一个极快的查询引擎，却花了六个月开发，而原本的研究一年只会查询几百次，这算成功吗？」

「不算。」你承认。

「假如它在正常输入下极快，但在历史数据修订、断档、异常值和并发修改时会给出错误答案呢？」

「也不算。」

「好。现在你终于开始定义问题了。」

你问他，是否所有宏大的设想都该被这样拆碎。

泡利答：「不。想象可以先走，证明必须跟上。一个不成熟的想法值得讨论；一个装成结论的不成熟想法必须被拦住。」

他又在黑板上画出三只盒子。

第一只写着：**错了。**

第二只写着：**不知道对不对。**

第三只写着：**连怎样判断对错都没说清楚。**

「别混淆这三件事。‘我还没有证据’不是‘我肯定错了’。而‘我说不清自己到底主张什么’，也不能通过增加更多公式和代码来修补。」

你忽然想到，AI 最擅长的一件事，恰恰是把第三只盒子包装得像第一流的研究成果：标题、架构、术语、分层、路线图，样样俱全。

泡利看着你关掉了那张过分漂亮的设计图。

「现在，」他说，「给你的研究系统一个最小、清楚、允许被否定的目标。」

## 第二幕：费曼，拿掉所有漂亮的词

费曼一直没有说话。他忽然把桌上的杯子往你面前推了推。

「先别建系统。讲一个具体的研究日。」

你说：每天早晨导入数据，写一个研究问题，运行实验，分析结果，再决定第二天做什么。

「很好。昨天最慢的是哪里？」

你想了想。「我不确定。有时候读数据慢，有时候实验多，有时候我不知道结果是不是可靠。」

「太好了！」费曼说。

你一愣，终于有人夸奖你了？

但他接着说：「我们找到第一个可以测量的未知数了。不是找到值得庆祝的架构，而是找到你还不知道什么。」

他拿出四张纸，一张写“读”，一张写“算”，一张写“验”，一张写“改”。

「假设你的一次研究总共要两个小时。读数据用了两分钟，计算用了八分钟，检查结果和重写假设用了一个半小时。你花三个月把数据查询提速十倍，究竟节约了多少？」

「大约一分多钟。」

「这说明查询引擎不重要吗？」

「对这次研究来说，不是最重要的。」

「正是如此。别把答案推广过度。你换一个计算密集、数据量极大的任务，结论可能完全相反。我们需要的是测量，而不是统一的口号。」

你提出另一种设想：「那我开五十个 Agent，同时替我研究，会不会把速度提升五十倍？」

费曼在纸上画了五十个小人，随后把所有小人的铅笔都连到同一个错误的公式上。

「假如他们都继承了你最开始那个错误前提，五十个 Agent 会更快地得到五十份错误报告。要是他们还互相引用，错觉就更壮观了。」

「那该怎么办？」

「先让五个 Agent 做不同的事。」他开始分纸条，「一个试图推翻假设，一个从经典文献中找成熟方案，一个做最小实现，一个检查数据，一个站在用户角度问：这到底有什么价值。然后你再观察，他们是不是真的提供了独立的信息。」

他又说：「不要只把 Agent 的数量当成变量。要看任务之间能否并行、是否共享错误前提、成果如何验证、互相沟通的成本有多大。」

说到这里，费曼拿起杯里的冰块。

「有时你会被一百页报告困住。那就想想，能不能找到一块冰、一根橡胶圈那样简单的实验，让争论从意见变成可观察的差异？」

他没有把每件事都变成玩具。复杂系统也需要复杂工具。但他始终要求，你能说清最简单的机制——究竟是哪一环，使你的方案比基线更好。

「你当然可以喜欢漂亮的架构，」他说，「只是不能让喜欢替你付事实的账。」

你问他，如果一个复杂想法没办法马上做实验，是不是就不值得想。

费曼摇头：「当然不是。假说可以很遥远；关键是你知道它现在属于想象、推论，还是证据。科学家不是只能谈已经证明的事，而是不能混淆这些事。」

## 第三幕：富兰克林，图像不等于真相

富兰克林终于把那张灯下的照片放到了桌面上。

「现在假设，你已经按费曼的建议，做了十组实验。有八组看起来不错。你会如何报告？」

「报告八组成功？」

「失败的两组呢？」

「也应该放进去。」

「为什么？」

你想了想：「因为否则就有选择性展示。」

她点头，却没有放过你。「还有，怎样定义‘成功’？是在实验前决定的，还是看到结果以后才决定的？你测量的是想要的现象，还是一个容易量到的替代指标？」

她拿出一个文件夹，里面有两幅画得近乎一样的曲线。

第一张曲线来自一个模型在训练数据上的拟合，第二张来自它在完全独立样本上的表现。第一张漂亮得让人兴奋，第二张只是普通。

「如果我只拿第一张给你看，你会说什么？」

「这模型很有潜力。」

「如果告诉你，参数是在看过这批数据之后反复调整出来的呢？」

「那我会谨慎一些。」

「如果这些数据中还混入了后来才知道的信息呢？」

你沉默了。

「错误并不总是造假。」她说。「有时它来自采样的方式、时间戳、仪器、缺失样本、图表纵轴、同一份数据被看了太多次，或者你心里早已偏爱一个解释。」

你说：「但如果每次都要求非常充分的证据，是不是会错过许多直觉上的突破？」

富兰克林把第一张曲线收起来，只留下第二张。

「直觉可以提出模型。数据有权拒绝它。你不需要等到拥有全部证据才开始研究，但不能在证据不足时宣称研究结束。」

你突然好奇：「你自己从来没有因为过分看重数据，错过一个方向吗？」

她微微笑了。

「怎么会没有？真实科学家会误判，会偏爱自己擅长的证据，会过于谨慎，也会过于大胆。我并非不会错。正因为我们会错，研究室才需要别人，也需要新的数据。」

桌上安静了一会儿。

这个回答比她宣称自己永远正确更有力。你终于理解，她不是让你对数字进行崇拜，而是要求数字、仪器、实验条件、竞争解释都经得起别人重查。

「记住，」她说，「图像可以启发模型，也可以误导模型。决定可信度的不是图画是否优美，而是从原始证据走到结论的每一步有没有得到允许。」

## 第四幕：三位导师第一次争吵

你觉得已经知道该怎样做了：「好，我先把整个研究系统的定义写到没有漏洞，再做最小实验，等数据完全充分以后，再开始大规模建设。」

泡利皱了皱眉。费曼笑出声。富兰克林先一步说：

「我们好像刚刚教出了一种新的错误。」

你愣住了。

费曼把那五十张 Agent 纸条扫到一边：「你这是准备把研究的所有不确定性，先在纸面上消灭。可有些东西必须碰到真实世界才知道。」

泡利补充：「逻辑严谨不是把每个变量先定义到宇宙毁灭。你必须先区分：哪几个假设如果错了，会使整个方案失去意义？」

富兰克林说：「我也没有要求数据‘完全充分’。证据永远有边界。我们想知道的是，在当前证据下能合理走到哪里，还不该走到哪里。」

三个人竟然在批评你刚刚从他们那里学到的话。

你不禁问：「那我该听谁的？」

泡利答：「别把我们变成新的权威。」

费曼说：「让能区分这些说法的实验发言。」

富兰克林说：「如果实验也有缺陷，就把缺陷写在结论旁边。」

于是你们一起重新审视最初的计划。

第一种方案，从零实现整套底层框架。它可能获得某些工程能力，但成本高，最先阻碍研究的瓶颈还没确认。

第二种方案，基于成熟库搭一个可以替换组件的薄系统。它会放弃一些极致控制，却允许更快拿到真实的瓶颈数据。

第三种方案，根本不造通用系统。先用一组脚本、现成数据处理工具和严格的实验记录，连续完成几次真实研究，再决定哪部分值得抽象。

你惊讶地发现，自己来之前只在讨论第一种方案里究竟选择哪门语言。你的思考始终在一个已经画好的盒子里进行。

泡利指着第三种方案：「有时最重要的推导，就是证明某个复杂前提根本不是必要条件。」

费曼说：「而且你可以先让第三种方案与第二种方案竞争，量一下完成一次可信研究到底需要多久。」

富兰克林接上：「记录失败的任务、返工次数、数据错误和审查时间。不要只看最快的那一天。」

你第一次觉得，导师并没有替你缩小世界；恰恰相反，他们把你没看见的两扇门打开了。

## 第五幕：当学生的想法确实是好的

又过了一段时间，你带来一个不起眼的新念头。

「我希望每次做研究时，都写一张很小的卡片：这个想法在声称什么，最容易推翻它的现象是什么，它在和哪个简单基线比较，以及实验有没有用到事后才获得的信息。卡片不要求写得漂亮，但要能让未来的我看懂。」

你准备好了接受又一轮批评。

泡利问：「是否每次都必须把四项写成一整篇论文？」

「不。几行就可以；重要实验再展开。」

「那你把最低必要定义和实施成本区分开了。」他说。

费曼问：「你准备怎样判断它有用？」

「先连续用两周，观察它有没有帮助我更早发现错误，以及是否妨碍探索。」

「这很好。你不只是设计了流程，也给流程本身设计了一个小实验。」

富兰克林问：「如果两周之后，你发现卡片很少填满，会怎么解释？」

「可能是设计太重，可能是我没有坚持，也可能是它确实没有价值。我需要看看究竟是哪一种。」

富兰克林合上文件夹：「那就去试。」

你惊讶地抬头：「这次没有人想推翻我？」

泡利说：「我们不是收取反对意见数量的顾问。」

费曼大笑：「如果一个想法小、便宜、能测量、失败了也容易撤回，非要给它编造一个致命缺陷，那才是愚蠢。」

富兰克林说：「不要把审查变成一场必须由批评者胜出的比赛。好思想需要证据支持，也需要有人有勇气承认它可能就是好思想。」

你这才真正放松下来。

因为现在你终于相信，这三个人的沉默不是敷衍，他们的赞同也不是讨好。

## 第六幕：缺失的课程

离开前，你提出最后一个担忧。

「我真正害怕的，也许还不是某一个想法错误，而是我没有足够的基础，甚至不知道自己漏掉了什么。我向 AI 问 A 和 B 哪个更好，它就能很认真地比较 A 和 B。但也许领域里有一个成熟的 C，早就把问题解决得更好。」

泡利没有立即回答。他在黑板上写了两个题目。

题目一：A 与 B 哪个更好？

题目二：我试图解决的真实问题是什么，现有最好的解决方法有哪些，A 与 B 各占什么位置？

「看到区别了吗？第二个问题改变了搜索空间。你问一个被限定的二选一问题，得到的往往就是一个精致的二选一答案。」

费曼接过话：「你应该允许导师说：‘你不需要在这两件事中选。先看看行业里别人是怎么做的，或者先问问你为什么需要这件事。’」

富兰克林补充：「但别让 AI 把它刚想出来的第三条路伪装成已被验证的成熟方案。它要告诉你：哪些是已有工作，哪些是类比，哪些只是可能更好的假说。需要时，应当查原始论文、文档和数据。」

你问：「如果我完全不知道某个基础概念呢？」

费曼说：「那就教。不是拿十个名词让你觉得自己知识不足。给你一个能亲手算的小例子，然后告诉你这个例子在哪些地方会失效。」

泡利说：「不是每个陌生名词都值得追。只补会改变当前判断的那个基础。」

富兰克林说：「同时明确，目前的证据还不能回答什么。清晰的未知，比虚假的完整更宝贵。」

他们于是帮你写下一条特别的规则：

「当学生给出一个方案时，先问：有没有一种不在方案里的已知路径，能够更简单、更可靠地解决原问题？如果有，必须主动展示；如果不知道，必须承认不知道并说明如何查证。」

这条规则比任何一句尖刻的评语都让你激动。

因为你并不需要一个只会说“不”的老师。

你需要一个能看到更多可能性的人。

## 尾声：门上新添的一行字

天快亮了。你收起电脑，发现自己的原计划并没有获得批准，也没有被彻底否决。

你带走了一个小实验、两条被忽略的路径、几项尚未证实的假设、一份可以推翻自己观点的证据清单，还有一个重新定义过的问题。

你觉得比带走一张完美的架构图更加踏实。

出门前，泡利说：「如果你的问题模糊，我们就要指出它模糊。哪怕你已经为这个问题工作了几个月。」

费曼说：「如果你的解释很漂亮，我们也要问它到底怎样工作。能不能拿出一个小小的现实例子？」

富兰克林说：「如果你的结论令人兴奋，我们就要问它究竟被什么支持。没有检验过，就不要假装检验过。」

你点点头。

他们又各自补了一句。

泡利：「但我们也可能误判。」

费曼：「所以欢迎你用实验反驳我们。」

富兰克林：「并且请保存你的证据。」

研究室的门在身后慢慢关上。

你回头看，门牌上不知何时多了一行字：

「这里也不负责证明你是错的。」

你笑了。

直到此刻，你才真正明白：
